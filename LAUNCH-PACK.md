# Spiral Truth V1.1.1 — Pacote de Lançamento Comercial

## Posicionamento

Uma experiência técnica interativa para investigar a diferença entre uma ação autorizada e o efeito efetivamente comprovado.

## Oferta

**Spiral Truth V1.1.1 — Founder / Proof-of-Concept**  
**R$197 — pagamento único**

## O comprador recebe

- acesso ao Live Lab;
- exploração do fluxo intenção → autorização → execução declarada → evidência → reconciliação;
- teste interativo de adulteração;
- verificação de integridade por SHA-256;
- exportação de relatórios;
- roteiro de exploração;
- documentação das limitações.

## O produto não é

- uma plataforma enterprise;
- um sistema de execução externa;
- uma auditoria formal;
- um backend multiusuário;
- um conector para ERP, sensores ou APIs;
- uma solução com assinatura Ed25519;
- uma prova independente de fatos operacionais reais.

## Roteiro de demonstração — 7 minutos

1. Apresente o problema: uma resposta HTTP 200 não comprova o efeito final.
2. Declare uma intenção.
3. Defina uma condição verificável.
4. Registre a execução declarada.
5. Mostre a evidência e a reconciliação.
6. Adultere um registro.
7. Execute a verificação de integridade.
8. Mostre o relatório exportado.
9. Explique claramente as limitações.
10. Convide o interessado a explorar o laboratório.

## Perguntas de descoberta

- Qual processo depende de uma ação digital produzir um efeito externo?
- Como vocês comprovam que o efeito aconteceu?
- O sistema de origem é também quem declara o sucesso?
- O que acontece quando a evidência chega atrasada?
- Como são tratados desvios e ausência de evidência?
- Existe diferença entre “aceito”, “executado” e “confirmado”?
- Qual processo teria maior custo se uma execução fosse apenas presumida?

## Mensagem comercial curta

O Spiral Truth não tenta substituir seus sistemas operacionais. Ele evidencia uma lacuna: a diferença entre uma instrução aceita e um resultado comprovado. A versão Founder é um Live Lab local para explorar esse problema, testar reconciliação e visualizar como uma trilha pode detectar adulterações e divergências.

## Critério para o próximo produto

O desenvolvimento de uma versão com backend e integrações deverá depender de um caso de uso real, com:

- fonte de intenção;
- fonte de evidência;
- critério de reconciliação;
- responsável pelo processo;
- desvio reproduzível;
- valor operacional mensurável.
